# Modbus RTU Guide (สำหรับ ESP32 + XY-MD03 / PZEM)

เอกสารนี้สรุปความรู้ Modbus ที่ใช้ในโปรเจกต์นี้ เรียงจากพื้นฐานไปถึงการแก้ปัญหา

> **หมายเหตุ:** ตัวเลข register ของ XY-MD03 (0x0101, 0x0102) สรุปจากคู่มือ XY-MD02/03 โดยความจำ
> ควรเทียบกับคู่มือของ sensor ที่ใช้จริงก่อนเขียนค่า ส่วนตัวอย่างเฟรมในเอกสารนี้คำนวณ CRC แล้ว แต่ยังไม่ได้ทดสอบกับ sensor จริง

---

## 1. Modbus คืออะไร

โปรโตคอลสื่อสารอนุกรมสำหรับงานอุตสาหกรรม ออกแบบโดย Modicon ปี 1979 ใช้อ่านค่าจาก sensor / มิเตอร์ และสั่งงานอุปกรณ์
จุดเด่นคือง่าย เปิดเผยฟรี และมีอุปกรณ์รองรับทั่วโลก

### Master / Slave
- **Master** (ในที่นี้คือ ESP32) เป็นฝ่ายถามเสมอ
- **Slave** (XY-MD03, PZEM) ตอบเมื่อถูกเรียกเท่านั้น ไม่พูดขึ้นมาเอง
- บัสหนึ่งมี master ได้ **ตัวเดียว** และมี slave ได้สูงสุด 247 ตัว (RS485 ต่อตรง ๆ ได้ราว 32 ตัวตามข้อกำหนดของวงจร)
- Slave แต่ละตัวมี **Slave ID (Address)** 1–247 ต้องไม่ซ้ำกันในบัสเดียวกัน

### รูปแบบ (Variant)
| แบบ | สื่อสารผ่าน | ข้อมูล | ตรวจความถูกต้อง |
|---|---|---|---|
| **RTU** | RS485 / RS232 | binary (กะทัดรัด) | CRC16 |
| ASCII | RS485 / RS232 | ข้อความ hex อ่านง่ายแต่ช้า | LRC |
| TCP | Ethernet / WiFi | binary ใน TCP (พอร์ต 502) | ไม่มี CRC (TCP ตรวจให้) |

โปรเจกต์นี้ใช้ **RTU**

## 2. โมเดลข้อมูล (Data Model)

ข้อมูลในอุปกรณ์แบ่งเป็น 4 ตาราง:

| ตาราง | ขนาด | สิทธิ์ | ตัวอย่าง | ชื่อเรียกแบบ Modicon |
|---|---|---|---|---|
| **Coil** | 1 bit | อ่าน + เขียน | สั่งรีเลย์ | 0xxxx |
| **Discrete Input** | 1 bit | อ่านอย่างเดียว | สถานะสวิตช์ | 1xxxx |
| **Input Register** | 16 bit | อ่านอย่างเดียว | ค่าวัด (temp, hum, แรงดัน) | 3xxxx |
| **Holding Register** | 16 bit | อ่าน + เขียน | ค่าตั้ง (ID, baud, setpoint) | 4xxxx |

### ข้อควรระวังเรื่อง Address
- ใน **โปรโตคอลจริง** address เริ่มที่ **0**
- คู่มือบางเล่มเขียนแบบ Modicon เช่น `40001` หมายถึง Holding Register ตัวแรก = address **0** ในเฟรม
- คู่มือบางเล่มเขียนเลข 1-based ถ้าอ่านได้ค่าของ register ข้างเคียง ให้ลอง **เลื่อน ±1**
- XY-MD03: Temp = 0x0001, Hum = 0x0002 (FC04) ตามที่ library ใช้อยู่

## 3. Function Code

| FC | ชื่อ | ทำอะไร | ใช้เมื่อ |
|---|---|---|---|
| 01 | Read Coils | อ่าน bit หลายตัว | ดูสถานะรีเลย์ |
| 02 | Read Discrete Inputs | อ่าน input แบบ bit | อ่านสวิตช์ |
| **03** | Read Holding Registers | อ่าน register อ่าน/เขียนได้ | อ่านค่าตั้ง (ID, baud) |
| **04** | Read Input Registers | อ่าน register อ่านอย่างเดียว | อ่านค่าวัด **(โปรเจกต์นี้ใช้)** |
| 05 | Write Single Coil | เขียน bit ตัวเดียว (`FF00`=ON, `0000`=OFF) | สั่งรีเลย์ |
| **06** | Write Single Register | เขียน register ตัวเดียว | ตั้ง ID / baud |
| 15 (0x0F) | Write Multiple Coils | เขียน bit หลายตัว | สั่งหลายช่องพร้อมกัน |
| 16 (0x10) | Write Multiple Registers | เขียน register หลายตัว | ตั้งค่าหลายค่าพร้อมกัน |

มี FC อื่นอีก (เช่น 07, 08 diagnostics, 22, 23) แต่แทบไม่ค่อยเจอในอุปกรณ์ sensor

**ข้อจำกัด:** อ่านได้สูงสุด 125 register หรือ 2000 bit ต่อคำสั่ง (เฟรม RTU ยาวสุด 256 ไบต์)

## 4. โครงสร้างเฟรม RTU

```
| Slave ID | Function | Data ...  | CRC Lo | CRC Hi |
|   1 B    |   1 B    |  0-252 B  |  1 B   |  1 B   |
```

- ข้อมูล 16 bit ส่งแบบ **big-endian** (ไบต์สูงก่อน)
- **CRC16** ส่งไบต์ **ต่ำก่อน** (กลับกับข้อมูล ซึ่งเป็นจุดที่คนสับสนบ่อย)
- CRC คำนวณจาก ID + FC + Data ด้วย polynomial 0xA001 ค่าเริ่ม 0xFFFF
- เฟรมถูกคั่นด้วย **ช่วงเงียบ ≥ 3.5 ตัวอักษร** (≈ 4 ms ที่ 9600 baud) และไบต์ในเฟรมเดียวกันห่างกันได้ไม่เกิน 1.5 ตัวอักษร

### ตัวอย่างที่ 1: อ่าน Temp/Hum (FC04) จาก ID 2

ESP32 ถาม (อ่าน 2 register เริ่มที่ 0x0001):
```
02  04  00 01  00 02  20 38
ID  FC  เริ่ม   จำนวน   CRC
```
Sensor ตอบ (Temp = 25.3 °C = 0x00FD, Hum = 60.5 % = 0x025D):
```
02  04  04  00 FD  02 5D  99 ED
ID  FC  ไบต์  Temp   Hum    CRC
        ข้อมูล
```
อ่านค่า: 0x00FD = 253 → หาร 10 = **25.3 °C**, 0x025D = 605 → **60.5 %**

### ตัวอย่างที่ 2: ตั้ง ID ใหม่ (FC06) — เปลี่ยนจาก ID 2 เป็น 3
```
02  06  01 01  00 03  99 C4
ID  FC  register  ค่าใหม่  CRC
```
Slave ตอบกลับเป็น **เฟรมเดียวกัน** (echo) แปลว่าสำเร็จ

### ตัวอย่างที่ 3: Slave ตอบ error
```
02  84  02  32 C1
ID  FC+0x80  รหัส error  CRC
```
FC ที่ตอบมาจะถูกตั้ง bit สูงสุด (04 → 84) บอกว่าคำสั่งนี้ล้มเหลว ตามด้วยรหัสสาเหตุ (02 = address ผิด)

## 5. รหัส Exception (Slave ตอบ error)

| รหัส | ชื่อ | ความหมาย |
|---|---|---|
| 01 | Illegal Function | ไม่รองรับ FC นี้ (เช่น ใช้ 03 กับ sensor ที่รองรับแค่ 04) |
| 02 | Illegal Data Address | address ที่ขอไม่มีในอุปกรณ์ |
| 03 | Illegal Data Value | ค่าที่ส่ง/จำนวนที่ขออยู่นอกช่วง |
| 04 | Slave Device Failure | อุปกรณ์เองผิดพลาด |
| 05 | Acknowledge | รับคำสั่งแล้ว ต้องใช้เวลาประมวลผลนาน |
| 06 | Slave Device Busy | กำลังทำงานอื่นอยู่ |

### รหัส error ของ ModbusMaster (ฝั่ง library ใน ESP32)
| รหัส | ชื่อ | ความหมาย |
|---|---|---|
| 0x00 | ku8MBSuccess | สำเร็จ |
| 0x01–0x04 | (จาก slave) | ตรงกับตารางข้างบน |
| 0xE0 | Invalid Slave ID | ID ที่ตอบกลับไม่ตรงกับที่ถาม |
| 0xE1 | Invalid Function | FC ที่ตอบกลับไม่ตรงกับที่ถาม |
| **0xE2** | **Response Timed Out** | ไม่มีใครตอบ (ไม่ต่อสาย, ID/baud ผิด, ไฟไม่มี) |
| 0xE3 | Invalid CRC | ข้อมูลเสียหายระหว่างทาง |

ถ้าเห็น **0xE2** แปลว่าไม่ได้ยินอะไรกลับมาเลย ให้เช็คฮาร์ดแวร์ก่อน (สาย, ไฟ, baud, ID)

## 6. ฮาร์ดแวร์: RS232 กับ RS485

| | RS232 | RS485 |
|---|---|---|
| สัญญาณ | single-ended (TX, RX, GND) | **differential** คู่ A/B |
| ระยะ | ~15 m | **~1200 m** |
| จำนวนอุปกรณ์ | จุดต่อจุด (1:1) | **หลายตัวบนสายเดียว (multi-drop)** |
| ทิศทาง | full-duplex | **half-duplex** (สลับกันส่ง/รับ) |
| ทนสัญญาณรบกวน | ต่ำ | **สูง** |

### Direction control
RS485 ส่งและรับพร้อมกันไม่ได้ ตัวแปลงต้องรู้ว่าตอนนี้ส่งหรือรับ มี 2 แบบ:
- **ใช้ขา DE/RE** ควบคุมด้วย GPIO (ต้องเขียนโค้ดสลับ)
- **Auto direction** วงจรตรวจจับเอง (บอร์ดนี้ใช้แบบนี้ จึงไม่ต้องมี DE/RE ในโค้ด)

### การเดินสาย RS485
- ใช้สาย **twisted pair** (บิดเกลียว) และควรมีชีลด์
- ต่อแบบ **daisy-chain** (เส้นเดียวไล่ต่อกัน) **ไม่ใช่แบบดาว** เพราะจะเกิดสัญญาณสะท้อน
- **Terminator 120 Ω** ที่ปลายสายทั้งสองด้าน (ระหว่าง A-B) จำเป็นเมื่อสายยาวหรือ baud สูง
- **Bias resistor** (pull-up ที่ A / pull-down ที่ B) ให้บัสว่างมีระดับสัญญาณชัดเจน บางโมดูลมีในตัว
- ต่อ **GND อ้างอิงร่วม** ถ้าอุปกรณ์ใช้ไฟคนละแหล่ง
- ผู้ผลิตตั้งชื่อ A/B **ไม่ตรงกัน** (บางยี่ห้อ A = D+, บางยี่ห้อกลับกัน) ถ้าไม่ตอบให้ลองสลับ A/B ก่อน เป็นวิธีแก้ที่ถูกที่สุด

## 7. พารามิเตอร์การสื่อสาร (ต้องตรงกันทั้งบัส)

| พารามิเตอร์ | ค่าที่โปรเจกต์นี้ใช้ | ค่าอื่นที่พบ |
|---|---|---|
| Baud rate | 9600 | 1200, 2400, 4800, 19200, 38400, 115200 |
| Data bits | 8 | |
| Parity | None | Even, Odd |
| Stop bits | 1 | 2 (มักใช้เมื่อ Parity = None ตามมาตรฐาน) |
| รหัสเรียก | **9600 8N1** | 9600 8E1 ฯลฯ |

> มาตรฐานแนะนำ 8E1 แต่อุปกรณ์ส่วนใหญ่ใช้ 8N1 ให้ดูคู่มือแต่ละรุ่น
> ในโค้ด: `Serial.begin(9600, SERIAL_8N1)`

## 8. การแปลงข้อมูลจาก register

register ละ 16 bit ไม่มีทศนิยมในตัว

| กรณี | วิธีแปลง | ตัวอย่าง |
|---|---|---|
| ค่าทศนิยม | หารตามคู่มือ | 253 ÷ 10 = 25.3 |
| ค่าติดลบ | แปลงเป็น **int16_t** (signed) | 0xFFFA → -6 → -0.6 °C |
| ค่า 32 bit | ใช้ 2 register รวมกัน | PZEM พลังงาน, power |
| float 32 bit | 2 register ตาม IEEE-754 | |

```cpp
int16_t raw = (int16_t)modbus.getResponseBuffer(0);   // รองรับค่าติดลบ
float temp = raw / 10.0;

uint32_t v = ((uint32_t)hi << 16) | lo;               // 32 bit (ลำดับ hi/lo ขึ้นกับผู้ผลิต)
```

> **จุดที่ระวัง:** library ในโปรเจกต์ปัจจุบัน (`DevXYMDSensor`) ใช้ `data / 10.0` แบบ unsigned
> ถ้า sensor อยู่ในที่เย็นกว่า 0 °C อุณหภูมิจะแสดงผิด (เช่น 6553.x) ถ้าจะใช้ในงานที่ติดลบได้ ควรแก้เป็น `int16_t`

**Word order ของค่า 32 bit** มี 2 แบบ (high word ก่อน หรือ low word ก่อน) ต่างกันตามผู้ผลิต ถ้าได้ค่าเพี้ยนเป็นเลขใหญ่มาก ให้ลองสลับ

## 9. หลักการเขียนโปรแกรม Master

1. **ถามทีละตัว** รอคำตอบหรือ timeout ก่อนค่อยถามตัวถัดไป
2. **อ่านหลาย register ในคำสั่งเดียว** (เช่น Temp+Hum 2 ตัว) เร็วกว่าถามแยกทีละตัว
3. **ตั้ง polling interval** ตามความจำเป็น (sensor อุณหภูมิ 1–2 วินาทีก็พอ)
4. **จัดการ timeout** ModbusMaster รอ 2 วินาทีถ้าไม่ตอบ ทำให้ `loop()` ค้าง โปรเจกต์นี้จึงถ่วงรอบอ่านเหลือ 15 วินาทีเมื่อไม่พบ sensor
5. **Retry** ลองใหม่ 2–3 ครั้งก่อนสรุปว่า sensor หาย (ในโค้ดใช้ `FAIL_LIMIT = 3`)
6. **มี fallback** เมื่ออ่านไม่ได้ (ในโปรเจกต์นี้คือค่าจำลอง) และแสดงสถานะให้ชัดว่าเป็น LIVE หรือ SIM
7. **หลายอุปกรณ์** ใช้ object แยกต่อ ID เดียวกัน Serial เดียวกัน เช่น
   ```cpp
   DevXYMDSensor s1(&Serial, 1);
   DevXYMDSensor s2(&Serial, 2);
   ```
   (ต้องเรียก `begin` ผ่าน object ใดตัวหนึ่งครั้งเดียวต่อ Serial และระวังว่า ModbusMaster ผูก ID ไว้กับ object)
8. **ห้าม `Serial.print` บน Serial0** ที่เป็นบัส RS485 ไม่งั้นข้อความ debug จะถูกส่งออกไปบนบัสและรบกวนการสื่อสาร ใช้ OLED หรือ web dashboard แสดงสถานะแทน

## 10. การตั้งค่า Sensor ผ่าน Modbus (XY-MD03)

| Register | หน้าที่ | ค่า |
|---|---|---|
| 0x0101 | Device Address (ID) | 1–247 |
| 0x0102 | Baud rate | 0=1200, 1=2400, 2=4800, 3=9600, 4=19200 |

(ตัวเลขเหล่านี้ให้ตรวจกับคู่มือรุ่นที่ใช้อีกครั้ง)

ขั้นตอนตั้ง ID:
1. ต่อ sensor **ตัวเดียว** กับ ESP32 (ตัวใหม่มักเป็น ID 1)
2. ส่ง FC06 เขียน register 0x0101 = ID ใหม่
   ```cpp
   modbus.begin(1, Serial);               // คุยกับ ID เดิม
   modbus.writeSingleRegister(0x0101, 2); // ตั้งเป็น ID 2
   ```
3. **ตัดไฟแล้วต่อใหม่** ค่าใหม่จึงมีผล
4. จดเลข ID ติดไว้ที่ตัว sensor
5. ค่อยต่อรวมบัสกับ sensor ตัวอื่น

ID ที่ใช้ได้: **1–247** (0 = broadcast ไม่มีการตอบกลับ, 248–255 สงวนไว้)

## 11. ข้อผิดพลาดที่พบบ่อย

| # | ปัญหา | อาการ | วิธีแก้ |
|---|---|---|---|
| 1 | สลับ FC03/FC04 | error 0x01/0x02 หรือไม่ตอบ | ดูคู่มือว่าใช้ตารางไหน |
| 2 | address เลื่อน 1 | ได้ค่าของ register ข้าง ๆ | ลอง ±1 |
| 3 | ลืมหารทศนิยม | ได้ 253 แทน 25.3 | หารตามคู่มือ |
| 4 | ไม่ใช้ signed | ค่าติดลบกลายเป็นเลขใหญ่ | ใช้ `int16_t` |
| 5 | word order 32 bit ผิด | ค่าเพี้ยนมาก | สลับ hi/lo |
| 6 | baud/parity ไม่ตรง | timeout หรือ CRC error | ตั้งให้ตรงทุกตัว |
| 7 | ID ซ้ำ / ID ผิด | ตอบชนกัน หรือไม่ตอบ | ตั้ง ID ให้ไม่ซ้ำ |
| 8 | ใช้ ID 0 | ไม่มีการตอบกลับ | ใช้ 1–247 |
| 9 | ถามถี่เกินไป | ตอบช้า/ข้อมูลชนกัน | เพิ่มระยะห่างระหว่างคำสั่ง |
| 10 | สาย A/B สลับ | ไม่ตอบเลย | สลับ A/B |
| 11 | ไม่มี terminator (สายยาว) | CRC error เป็นระยะ | ใส่ 120 Ω ปลายสาย |
| 12 | ไม่มีกราวด์ร่วม | ข้อมูลเพี้ยน/ไม่เสถียร | ต่อ GND อ้างอิง |
| 13 | เขียน ID/baud แล้วไม่ restart | ยังเป็นค่าเดิม | ตัดไฟ sensor |
| 14 | Serial.print บน Serial0 | บัสรวน | เลิก print |
| 15 | ต่อแบบดาว | สัญญาณสะท้อน | ใช้ daisy-chain |
| 16 | ไฟเลี้ยง sensor ไม่พอ | รีเซ็ตเป็นช่วง ๆ | เช็คแรงดัน/กระแส |

## 12. แผนผังตรวจปัญหา (ไม่ตอบ / ได้ SIMULATION)

เรียงจากง่ายและถูกที่สุดไปยาก:

1. **ไฟเลี้ยง sensor** มีไฟหรือไม่ (มีไฟ LED/หน้าจอ sensor ติดไหม)
2. **สลับ switch RS232/RS485** ถูกโหมดหรือยัง
3. **สาย A/B** ลองสลับ
4. **Baud / Parity / Stop bit** ตรงกับ sensor หรือไม่
5. **Slave ID** ในโค้ดตรงกับที่ตั้งใน sensor หรือไม่ (ค่าโรงงาน = 1)
6. **FC และ address** ตรงกับคู่มือหรือไม่
7. **ดูรหัส error:** 0xE2 = ไม่มีตอบ (ข้อ 1–5), 0xE3 = สัญญาณรบกวน (terminator, GND, สาย), 0x01/0x02 = FC/address ผิด
8. **ทดสอบด้วยเครื่องมืออื่น** ต่อ sensor กับ PC ผ่าน USB-RS485 แล้วใช้ Modbus Poll (Windows) หรือ `mbpoll` (Mac/Linux) เพื่อแยกว่าปัญหาอยู่ที่ sensor หรือโค้ด
   ```bash
   mbpoll -m rtu -a 2 -b 9600 -P none -t 3 -r 1 -c 2 /dev/tty.usbserial-XXXX
   ```
   (`-t 3` = input register / FC04, `-t 4` = holding register / FC03)
9. **วัดแรงดัน A–B** ด้วยมัลติมิเตอร์ ขณะบัสว่างควรได้ราว +0.2 V ขึ้นไป (A สูงกว่า B ตามผู้ผลิตส่วนใหญ่)

---

## 13. เครื่องมือที่ช่วยเรียนรู้ / debug

- **Modbus Poll / Modbus Slave** (Windows) ใช้เป็น master/จำลอง slave
- **mbpoll** (command line, Mac/Linux)
- **QModMaster** (ฟรี หลายแพลตฟอร์ม)
- **USB-RS485 adapter** (ต่อกับ PC)
- **Logic analyzer** ดักสัญญาณดูเฟรมจริง
- ESP32 เองก็เขียนโปรแกรมเป็น slave จำลองได้ถ้าอยากฝึก

## 14. คำศัพท์สั้น ๆ

| คำ | ความหมาย |
|---|---|
| Master / Slave | ผู้ถาม / ผู้ตอบ |
| Slave ID / Address | เลขประจำอุปกรณ์ (1–247) |
| FC | Function Code (ประเภทคำสั่ง) |
| Register | ช่องข้อมูล 16 bit |
| Coil | ช่องข้อมูล 1 bit อ่าน/เขียนได้ |
| CRC | ค่าตรวจสอบความถูกต้องของเฟรม |
| Broadcast | ส่งหาทุกตัว (ID 0) ไม่มีใครตอบ |
| Half-duplex | ส่งและรับสลับกัน ไม่พร้อมกัน |
| Daisy-chain | ต่ออุปกรณ์เป็นเส้นเดียวไล่กันไป |
| Terminator | ตัวต้านทาน 120 Ω ปลายสาย กันสัญญาณสะท้อน |
| Timeout | เวลารอคำตอบก่อนถือว่าไม่ตอบ |
